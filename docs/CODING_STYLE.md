# 코딩 스타일

이 규칙은 [reJSRF의 CODING_STYLE](https://github.com/nworkers/reJSRF/blob/main/docs/CODING_STYLE.md)과 같다(원래 [rePIU의 CODING_STYLE](https://github.com/reexec/rePIU/blob/main/docs/CODING_STYLE.md)에서 왔다). 공유 런타임의 코드는 [rexbox의 CODING_STYLE](https://github.com/reexec/rexbox/blob/main/docs/CODING_STYLE.md)을 따르며 내용은 같다.

These rules are those of [reJSRF's CODING_STYLE](https://github.com/nworkers/reJSRF/blob/main/docs/CODING_STYLE.md) (originally from [rePIU's CODING_STYLE](https://github.com/reexec/rePIU/blob/main/docs/CODING_STYLE.md)). The shared runtime's code follows [rexbox's CODING_STYLE](https://github.com/reexec/rexbox/blob/main/docs/CODING_STYLE.md), which says the same.

## 기본 원칙

* 타이틀 코드, 도구, 앱의 C++ 코드는 C++20을 기준으로 작성한다.
* 기본 기준은 Google C++ Style Guide를 따른다. 프로젝트 예외 규칙은 아래 항목으로 명시한다.
* 원본 실행 파일의 동작 보존을 우선하며, 편의를 위한 게임 로직 재작성은 피한다.
* 플랫폼 공용 코어와 플랫폼 종속 구현을 분리한다(플랫폼 구현은 rexbox에 있다).
* 큰 구조 변경은 설계 문서에 근거를 남긴다.
* 새 기능에는 최소 검증 절차를 함께 문서화한다.
* 독립된 책임을 갖는 큰 기능은 전용 header/source pair로 분리한다.
* 앱 진입점에는 orchestration만 둔다.

## Basic Principles

* Write the title, tool and app C++ code against C++20.
* Follow the Google C++ Style Guide as the baseline. Project-specific exceptions are defined below.
* Prioritize preserving original executable behavior and avoid rewriting game logic for convenience.
* Separate the platform-neutral core from platform-specific implementations (the platform implementations live in rexbox).
* Document the rationale for large structural changes in design documents.
* Document a minimum verification procedure with each new feature.
* Give major independently responsible features dedicated header/source pairs.
* Keep only orchestration in the application entry point.

## 프로젝트 예외 규칙

* 여는 중괄호 `{` 는 같은 줄 끝에 두지 않고 다음 줄에 둔다. 한 줄 접근자(`int size() const { return size_; }`)는 예외로 허용한다.
* 탭 문자는 사용하지 않는다.
* 들여쓰기는 공백 4칸을 사용한다.
* 함수명은 `PascalCase`, 변수명은 `snake_case`, 클래스 멤버 변수는 `snake_case_`, 상수는 `kPascalCase`를 사용한다.
* C++ 소스 파일 확장자는 `.cpp`, 헤더는 `.h`를 사용한다. C 소스는 `.c`를 사용한다.
* 네임스페이스: 공유 런타임은 `rexbox::<layer>`(예: `rexbox::hle::d3d8`), 타이틀 코드는 `rect3`.
* include 경로는 `include/` 기준(`"rect3/ct3_profile.h"`, `"rexbox/runtime/guest_memory.h"`)으로 쓴다.
* include guard는 경로를 대문자로 바꾼 `RECT3_CT3_PROFILE_H` 형식을 쓴다.

## Project-Specific Exceptions

* Place opening braces `{` on the next line instead of at the end of the current line. One-line accessors (`int size() const { return size_; }`) are allowed as an exception.
* Do not use tab characters.
* Use four spaces for indentation.
* Use `PascalCase` for functions, `snake_case` for variables, `snake_case_` for class members, and `kPascalCase` for constants.
* Use `.cpp` for C++ sources and `.h` for headers. C sources use `.c`.
* Namespaces: the shared runtime uses `rexbox::<layer>` (for example `rexbox::hle::d3d8`); title code uses `rect3`.
* Write include paths relative to `include/` (`"rect3/ct3_profile.h"`, `"rexbox/runtime/guest_memory.h"`).
* Include guards spell the path in upper case, as in `RECT3_CT3_PROFILE_H`.

## 재컴파일 코드와 디컴파일 코드

* 파이프라인이 생성한 C 코드는 스타일 규칙의 적용 대상이 아니며, 손으로 고치지 않는다. 바꿔야 하면 생성기나 생성기 설정을 고친다.
* 디컴파일 함수는 lifter와 링커가 찾을 수 있도록 대체하는 함수와 같은 심볼 `void sub_XXXXXXXX(void)`로 정의하고, 주석에 주소, 호출 규약, 의미 있는 시그니처를 적는다. lift 본문과 비교하려면 `extern void sub_XXXXXXXX_gen(void);`을 선언한다.
* 디컴파일 코드는 게스트 메모리를 `MEM8/16/32` 같은 런타임 접근 매크로로 다루고, 레지스터는 `g_eax` 같은 전역 이름으로 쓴다(`eax` 같은 짧은 이름은 생성 코드 전용). 게스트 구조체를 호스트 포인터로 직접 캐스팅하지 않는다(64비트 호스트에서 포인터 크기가 다르기 때문).
* 디컴파일 함수마다 재컴파일 버전과 비교하는 검증 방법을 작업 로그에 남긴다.

## Recompiled and Decompiled Code

* C code generated by the pipeline is outside the style rules and is never edited by hand. If it must change, change the generator or its configuration.
* A decompiled function is defined under the same symbol as the function it replaces, `void sub_XXXXXXXX(void)`, so the lifter and the linker find it; its comment gives the address, calling convention and a meaningful signature. To compare it with the lifted body, declare `extern void sub_XXXXXXXX_gen(void);`.
* Decompiled code handles guest memory through the runtime's access macros (`MEM8/16/32`) and registers through the global names (`g_eax`; short names like `eax` are for generated code only). Do not cast guest structures straight to host pointers (pointer sizes differ on 64-bit hosts).
* For each decompiled function, the work log records how it was compared with its recompiled version.

## 주석 언어

* **소스 코드의 주석은 영어로만 작성한다.** 한국어 주석과 한국어·영어 이중 언어 주석을 두지 않는다. 같은 내용을 두 벌 유지하면 한쪽만 갱신되어 어긋난다.
* 이 규칙은 문서 규칙과 다르다. `docs/` 아래 Markdown 문서는 한국어를 먼저 쓰고 영어 번역을 덧붙이지만, 소스 주석은 영어 한 벌만 둔다.
* 커밋 메시지, 코드 식별자, 로그 문자열도 영어를 사용한다.
* 적용 대상은 C/C++ 소스·헤더와 빌드·스크립트(`scripts/`, `CMakeLists.txt`, 워크플로 파일)를 포함한 저장소의 모든 코드다. `third_party/` 아래 외부 코드는 원본 그대로 둔다.

## Comment Language

* **Write source-code comments in English only.** Do not keep Korean or bilingual comments; two copies of one explanation drift apart.
* This differs from the documentation rule: Markdown under `docs/` leads with Korean and adds English, while source comments carry one English copy only.
* Commit messages, code identifiers and log strings are English as well.
* The scope is all code in the repository, including C/C++ sources and headers and the build and script files (`scripts/`, `CMakeLists.txt`, workflow files). External code under `third_party/` stays as upstream wrote it.

## 디렉터리 정책

* 공유 런타임과 플랫폼 계층은 `third_party/rexbox`에 있다. 이 저장소는 그 공개 헤더 `include/rexbox/`만 include한다.
* 타이틀 코드는 `include/rect3/`, `src/game/ct3/`에 둔다. 디컴파일 함수는 `src/game/ct3/decomp/`, 재컴파일 설정은 `src/game/ct3/recomp/`.
* 앱은 `src/app/`에 둔다.
* 헤더에서 플랫폼을 고르는 `#if`는 두지 않는다(플랫폼 선택은 rexbox의 일이다).

## Directory Policy

* The shared runtime and platform layer live in `third_party/rexbox`; this repository includes only its public headers under `include/rexbox/`.
* Title code goes in `include/rect3/` and `src/game/ct3/`: decompiled functions in `src/game/ct3/decomp/`, the recompilation configuration in `src/game/ct3/recomp/`.
* The app goes in `src/app/`.
* No `#if` chooses a platform in a header here (platform selection is rexbox's job).
