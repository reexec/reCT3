## 검증: B1·E4

숨긴 어트랙트 데모 6개 동시 실행, 130초, 4묶음씩:

| 빌드 | 실행 | 음악 멈춤 | stall | null 호출 | 잠금 시한 | `recomp_unimpl` |
|---|---|---|---|---|---|---|
| 기준 v0.17.0 | 24 | 0 | 6(한 묶음 6개가 같은 순간) | 0 | 0 | 0 |
| 실험 v0.18.0 | 24 | 3(한 실행) | 2(같은 실행) | 0 | 1(같은 실행) | 0 |

* 기준의 stall 6: 묶음 b17d의 6개 실행이 같은 순간 11~12초 멈췄다가 이어졌다. thread 2는 게임 코드에서 돌고 있었고 잠금과 상관이 없었다. 여섯 프로세스가 동시에 멈춘 것이라 호스트 전체의 일시 정지로 본다(**추정**).
* 실험의 한 실행(e18a3): thread 2가 `sub_000B3060`에서 CRI ADXM 호스트 잠금을 쥔 채 safe thread(mwidle)를 깨우려고 돈다. 그 safe thread와 vsync·파일 서버 스레드는 그 잠금을 기다렸다. 2초 잠금 시한 뒤 풀렸다가 되풀이됐다.
  * 생성 코드와 상관없는 기존 경쟁이다. 두 버전의 생성 코드는 기능상 같다.
  * #52로 따로 연다.
* 주행(v0.18.0 빌드, `scripts/drive_west_coast.ps1 -Exe`): 59.4~59.8 fps(draw 약 800), 멈춤·null 호출·stall·잠금 시한 없음.

## Verification: B1 and E4

Six hidden attract demos in parallel, 130 s, four batches each:

| Build | Runs | Music stops | Stalls | Null calls | Lock timeouts | `recomp_unimpl` |
|---|---|---|---|---|---|---|
| Baseline v0.17.0 | 24 | 0 | 6 (one batch's six runs at the same moment) | 0 | 0 | 0 |
| Experiment v0.18.0 | 24 | 3 (one run) | 2 (the same run) | 0 | 1 (the same run) | 0 |

* The baseline's 6 stalls: batch b17d's six runs all paused for 11–12 s at the same moment and went on. Thread 2 was running game code with no lock involved; six processes pausing together is taken to be a host-wide pause (**inferred**).
* The experiment's one run (e18a3): thread 2 spins in `sub_000B3060`, holding the CRI ADXM host lock while waking the safe thread (mwidle), and that safe thread, the vsync thread and the file server wait for the lock; the 2 s lock timeout breaks it, and it repeats.
  * An existing race unrelated to the generated code, which is functionally the same in both versions.
  * Opened separately as #52.
* Drive (the v0.18.0 build, `scripts/drive_west_coast.ps1 -Exe`): 59.4–59.8 fps (about 800 draws), no stops, null calls, stalls or lock timeouts.

## Verdict: adopt

Design section 6: the generated result is functionally the same and every criterion holds.
