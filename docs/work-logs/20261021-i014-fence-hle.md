# 작업 로그: Start 뒤 `D3DDevice_InsertFence`에서 멈춤 — 완료 (issue #14)

작업 지시: [20261021-i014-fence-hle](../work-orders/20261021-i014-fence-hle.md) · rexbox: issue #19, [작업 로그](../../third_party/rexbox/docs/work-logs/20261021-i019-fence-exports.md)

## 한 일

1. 원인 확인: 타이틀에서 Start를 누르면 스레드 2가 `stopped at unimplemented XDK function D3D8 D3DDevice_InsertFence (000F5050)`으로 멈춘다. 프레임 코드 `0005E7B8`이 `InsertFence`를, `0005E859`가 `BlockOnFence([esp+0x1C])`를 부른다. lift된 4531 라이브러리에서 `InsertFence`는 `D3D_SetFence(0)`, `BlockOnFence(f)`는 `D3D_BlockOnTime(f, 0)`이다(분석 §7).
2. rexbox #19에 세 펜스 export(`InsertFence`, `BlockOnFence`, `IsFencePending`)를 넣고, submodule을 그 작업 브랜치 `i019-fence-hle`의 `4a54012`로 올렸다(v0.0.7 `0aa0126` 위의 커밋 3개). rexbox가 머지되기 전까지의 임시 고정이다.
3. HLE export는 이름으로 묶이므로 재생성 없이 빌드했다.

## 검증

입력은 `REXBOX_INPUT=keyboard`. 키는 `PostMessage`(`WM_KEYDOWN`/`WM_KEYUP`)로 게임 창에만 보냈다. `SetForegroundWindow` + `keybd_event`로 보낸 첫 시도는 창이 포커스를 얻지 못해 게임에 닿지 않았다.

| Win32 x86 Release, CTest | 오류 0, 5/5 |
| 기준: 이 변경 없는 exe(HLE export 314개), Start | 스레드 2가 `D3DDevice_InsertFence (000F5050)`에서 멈추고 70초에 종료 |
| 이 변경(export 317개), `REXBOX_HLE_FALLBACK` 없음, 40초부터 3초마다 Enter/Z, 240초 | 미구현 HLE 정지 없음. frame 1200 모드 선택, 1500 West Coast, 1800 로딩 팁, 2100–6000 운전(제한 시간 50 → 36, 교통 이동; Enter가 일시정지 메뉴를 번갈아 연다), 60 fps |

## 남은 것

* rexbox `i019-fence-hle`의 머지와 submodule의 머지 커밋 고정.
* 운전 중의 화면 오류(모델 깨짐 등)는 이 작업에서 보지 않았다. 일시정지 메뉴가 없는 플레이는 사용자 환경에서 확인한다.

# Work log: the stop at `D3DDevice_InsertFence` after Start — done (issue #14)

Work order: [20261021-i014-fence-hle](../work-orders/20261021-i014-fence-hle.md) · rexbox: issue #19, [work log](../../third_party/rexbox/docs/work-logs/20261021-i019-fence-exports.md)

Done: (1) Pressing Start on the title screen stops thread 2 with `stopped at unimplemented XDK function D3D8 D3DDevice_InsertFence (000F5050)`. The frame code `0005E7B8` calls `InsertFence` and `0005E859` calls `BlockOnFence([esp+0x1C])`; in the lifted 4531 library `InsertFence` is `D3D_SetFence(0)` and `BlockOnFence(f)` is `D3D_BlockOnTime(f, 0)` (analysis section 7). (2) rexbox #19 added the three fence exports (`InsertFence`, `BlockOnFence`, `IsFencePending`), and the submodule moved to `4a54012` on its task branch `i019-fence-hle` (three commits on v0.0.7 `0aa0126`), a temporary pin until rexbox merges. (3) HLE exports bind by name, so the build needed no regeneration.

Verification: input through `REXBOX_INPUT=keyboard`, with keys sent to the game window alone by `PostMessage` (`WM_KEYDOWN`/`WM_KEYUP`); a first attempt with `SetForegroundWindow` + `keybd_event` never reached the game because its window did not get focus. Win32 x86 Release builds with no errors and CTest passes 5/5. Baseline: the exe without this change (314 HLE exports) stops on thread 2 at `D3DDevice_InsertFence (000F5050)` after Start and ends at 70 s. With this change (317 exports), no `REXBOX_HLE_FALLBACK`, Enter/Z every 3 s from 40 s, 240 s: no unimplemented-HLE stop; frame 1200 shows mode selection, 1500 West Coast, 1800 a loading tip, and 2100 to 6000 the taxi driving (time limit 50 down to 36, traffic moving; the Enter presses toggle the pause menu) at 60 fps.

Left: merging rexbox `i019-fence-hle` and pinning the submodule to its merge commit. Rendering faults while driving were not examined here; play without the pause menu is checked on the user's machine.
