# 작업 로그: Linux 가이드의 i386 설치가 glib 2.80.0-6ubuntu3.10에서 멈춘다 (issue #39)

작업 지시: [20261103-i039](../work-orders/20261103-i039-linux-glib-i386.md) · rexbox #46

## 원인

rexbox CI 러너에서 확인했다([rexbox 작업 로그](../../third_party/rexbox/docs/work-logs/20261103-i046-ci-glib-i386.md)). glib 2.80.0-6ubuntu3.10의 개발 파일은 `python3 | qemu-user | qemu-user-static`에 의존한다. `libpulse-dev:i386`을 통해 i386 판이 함께 설치되는데, i386 패키지에서 이 `python3`는 i386 `python3`다. i386 목록을 한 번에 설치하면 apt가 그것을 골라 설치된 amd64 Python과 충돌하고, `held broken packages`로 멈춘다. 이 가이드의 x86 설치도 같은 목록이다.

## 한 일

* `docs/guides/linux-setup-and-build.md`: x86 설치 앞에 `sudo apt-get install -y libglib2.0-dev-bin qemu-user`를 넣었다. 그것을 빠뜨렸을 때의 증상을 적었다(한국어·영어).
* `third_party/rexbox`를 v0.0.21(`bc21519`)로 올렸다. CI와 가이드의 같은 수정이 들어 있고, 코드 변경은 없다. ARCHITECTURE의 submodule 표기를 고쳤다.

## 검증

| 검증 | 결과 |
|---|---|
| WSL2 Ubuntu 24.04, 가이드 설치 시뮬레이션(`apt-get install -s`, 선행 설치와 i386 목록) | 풀림 |
| rexbox CI(같은 선행 설치) | Linux x86 Debug·Release 포함 6개 작업 통과, v0.0.21 릴리스 워크플로 통과 |

* WSL2에는 glib 개발 패키지가 이미 있어서, 수정 전의 실패는 이 환경에서 재현되지 않는다. 실패 재현은 rexbox CI 러너로 했다.

# Work log: the Linux guide's i386 install stops on glib 2.80.0-6ubuntu3.10 (issue #39)

Work order: [20261103-i039](../work-orders/20261103-i039-linux-glib-i386.md) · rexbox #46

Cause, confirmed on rexbox's CI runner ([rexbox work log](../../third_party/rexbox/docs/work-logs/20261103-i046-ci-glib-i386.md)): glib 2.80.0-6ubuntu3.10's development files depend on `python3 | qemu-user | qemu-user-static`; their i386 version comes in through `libpulse-dev:i386`, and for an i386 package that `python3` is `python3:i386`. Installing the i386 list at once, apt takes it, clashes with the installed amd64 Python and stops with `held broken packages`. This guide's x86 install is the same list.

Done: `docs/guides/linux-setup-and-build.md` puts `sudo apt-get install -y libglib2.0-dev-bin qemu-user` before the x86 install and describes the symptom when it is missed (Korean and English); `third_party/rexbox` moves to v0.0.21 (`bc21519`), which carries the same fix in its CI and guide and no code change; the submodule entry in ARCHITECTURE is updated.

Verification: on WSL2 Ubuntu 24.04 the guide's install (the first step and the i386 list) resolves in simulation (`apt-get install -s`); rexbox's CI with the same first step passes all six jobs, Linux x86 Debug and Release among them, and its v0.0.21 release workflow passes. WSL2 already has glib's development packages, so the failure before the fix does not reproduce there; it was reproduced on rexbox's CI runner.
