## reCT3 v0.0.19

이전 릴리스 **v0.0.18** 이후의 변경입니다(issue #20 2차). **운전이 시작될 때 셰이더 프로그램을 한꺼번에 불러오느라 생기던 끊김이 줄어듭니다.** rexbox를 v0.0.20으로 올립니다.

### issue

| issue | 내용 | 커밋 |
|---|---|---|
| [#20](https://github.com/reexec/reCT3/issues/20) (2차, 열림) | 운전 화면 프레임 시간: 긴 프레임 찾기, 프로그램 캐시 미리 올리기 | `d88a59d`, `04c47b3`, `da5c94b` |

### 바뀐 것

* **rexbox v0.0.19 → v0.0.20**(`c98fc2a`, reexec/rexbox#23 2차): 셰이더 프로그램 캐시를 표시 스레드가 vblank를 기다리는 시간에 미리 올린다(파일은 읽기 스레드가 읽는다). `REXBOX_SHADER_WARM=<n>`(기본 1024, 0이면 끔). 긴 프레임 진단 `REXBOX_D3D8_SLOW_FRAME=<ms>`는 프레임의 텍스처·프로그램 시간을 보고하고, 측정하는 프레임을 늦추지 않는다.
* 문서: 작업 로그 i020(2차), ARCHITECTURE의 submodule 표기.

### 확인한 것

| 구성 | 확인 |
|---|---|
| Win32 x86 Release(Ryzen 5 5600X, RTX 4090) | 경고 0(생성 코드의 기존 D9025 제외), CTest 7/7 |
| 운전 진입, 미리 올리기 켬/끔 번갈아 3쌍 | 장면 시작의 프로그램 74개 4~5 ms 대 40~42 ms, 최악 프레임 50~51 ms 대 58~61 ms, 부팅 구간 fps 같음 |
| 꾸준한 운전 | 59.8 fps(v0.0.12 기준과 같음) |

### 알려진 한계

* 운전 시작의 텍스처 업로드(112개 15 ms, 가끔 56 ms)와 카메라 도입부의 그리기 수가 많은 프레임은 그대로다(#20 계속).
* 재생성은 필요 없다(v0.0.18에서 재생성했다면). main으로 옮긴 뒤 `scripts/recomp/regenerate.py`를 하지 않으면 decomp 대체가 빠진 채 링크된다.

## reCT3 v0.0.19 (English)

Changes since **v0.0.18** (issue #20, second pass). **Fewer hitches at the start of driving, where the title loads dozens of shader programs at once.** rexbox moves to v0.0.20.

Issue: #20 (second pass, still open): driving frame time, finding the long frames and warming the program cache (`d88a59d`, `04c47b3`, `da5c94b`).

Changes: rexbox v0.0.19 → v0.0.20 (`c98fc2a`, reexec/rexbox#23 second pass): the shader program cache is warmed while the presenting thread waits for the vertical blank (a reader thread reads the files), `REXBOX_SHADER_WARM=<n>` (default 1024, 0 off); the long-frame diagnostic `REXBOX_D3D8_SLOW_FRAME=<ms>` reports a frame's texture and program times and no longer delays the frames it measures. Documents: work log i020 (second pass), the submodule entry in ARCHITECTURE.

Verified: Win32 x86 Release (Ryzen 5 5600X, RTX 4090) with 0 warnings (apart from the generated code's existing D9025) and CTest 7/7; three alternating warming on/off pairs into driving: 74 programs at the scene start in 4–5 ms against 40–42 ms, worst frame 50–51 ms against 58–61 ms, the same boot fps; steady driving at 59.8 fps, as the v0.0.12 baseline.

Known limits: the texture uploads at the start of driving (112 in 15 ms, sometimes 56 ms) and the camera intro's many-draw frames are unchanged (#20 continues). No regeneration is needed if v0.0.18 was regenerated; after moving to a new main, skipping `scripts/recomp/regenerate.py` links without the decomp replacements.
