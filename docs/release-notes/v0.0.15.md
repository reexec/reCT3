## reCT3 v0.0.15

이전 릴리스 **v0.0.14** 이후의 변경입니다(issue #25 후속, issue #29). **Linux 실기에서 재컴파일 코드 생성부터 실행까지 확인하고 가이드를 실기 기준으로 다시 씁니다. CRI ADXM 잠금 콜백에 호스트 상호 배제를 넣습니다.**

### 관련 issue

| issue | 내용 | 커밋 |
|---|---|---|
| [#25](https://github.com/reexec/reCT3/issues/25) | Linux 실기 후속: `regenerate.py`가 Linux 빌드 트리에서 `rexbox_xdk_symbols`를 찾음, 가이드와 README | `f8ea228` |
| [#29](https://github.com/reexec/reCT3/issues/29) (열려 있음) | CRI ADXM 잠금 콜백의 호스트 상호 배제, 음악 반복 진단 기록 | `b7d364f`, `a7a5f9a`, 이 릴리스의 마지막 커밋 |

### 바뀐 것

* **Linux 실기**: `scripts/recomp/regenerate.py`가 `rexbox_xdk_symbols`를 `build/linux-<arch>-<config>`와 `$RECT3_BUILD_DIR` 아래에서도 찾는다. `scripts/build_linux.sh`를 git에 실행 권한으로 둔다.
* **가이드**: [Linux 가이드](../guides/linux-setup-and-build.md)를 실기 기준으로 다시 썼다. 순서는 apt 패키지(`python3-capstone`, x86용 i386 판 전체 목록), 도구 빌드, 생성, 빌드, 실행이고 WSL2는 한 절로 줄였다. README에 Linux 빌드 절과 플랫폼 표를 더했다.
* **CRI ADXM 잠금**(`src/game/ct3/decomp/adxm_lock.c`, reJSRF #68/#91/#100의 이식): SVM 잠금 콜백 `000B2FF0`, `000B3030`을 rexbox 게스트 잠금으로 감싸고, 우선순위를 스레드마다 되돌리고, `000BB9C0`이 이 스레드의 깊이만큼만 푼다. 분석: [cri-middleware](../analysis/cri-middleware.md), 설계: [i029](../design/20261027-i029-adxm-lock.md).
* submodule 변경 없음(rexbox v0.0.17 `f4a6a48`).

### 알려진 한계

* **플레이 중 음악이 한 구간(0.34초)을 반복하는 문제(issue #29)가 남아 있다.** 어댑터로는 없어지지 않았다. 반복이 시작되면 음악 출력 버퍼가 바뀌지 않고 ADX 파일 읽기가 멈춘다. CRI 서버 세 개가 호스트에서 동시에 도는 것이 원인 후보다. 진단 내용: [작업 로그 i029](../work-logs/20261027-i029-adxm-lock.md).
* 실기의 x86 빌드는 i386 패키지(`libxss-dev:i386`, `libxtst-dev:i386`)가 없어 확인하지 못했다.
* 이 버전으로 올린 뒤 **`scripts/recomp/regenerate.py`를 다시 실행**해야 한다(어댑터 함수가 lift 대상에서 빠지고 `_gen` 본문이 생긴다).

## reCT3 v0.0.15 (English)

Changes since **v0.0.14** (issue #25 follow-up, issue #29). **Checks generation through running on a Linux machine and rewrites the guide for it, and adds host mutual exclusion to the CRI ADXM lock callbacks.**

Issues: #25, the Linux-machine follow-up: `regenerate.py` finds `rexbox_xdk_symbols` in the Linux build trees, guide and README (`f8ea228`); #29 (still open), host mutual exclusion for the CRI ADXM lock callbacks and the record of the music-repeat diagnosis (`b7d364f`, `a7a5f9a` and the last commit of this release).

Changes: `scripts/recomp/regenerate.py` also looks for `rexbox_xdk_symbols` under `build/linux-<arch>-<config>` and `$RECT3_BUILD_DIR`, and `scripts/build_linux.sh` is executable in git. The [Linux guide](../guides/linux-setup-and-build.md) is rewritten for a Linux machine (apt packages with `python3-capstone` and the full i386 list for x86, the tool build, generation, build, run), WSL2 shrinking to one section; README gains a Linux build section and platform rows. `src/game/ct3/decomp/adxm_lock.c` ports reJSRF #68/#91/#100: the SVM lock callbacks `000B2FF0` and `000B3030` are wrapped in a rexbox guest lock, each thread's own priority is restored, and `000BB9C0` releases only this thread's depth ([analysis](../analysis/cri-middleware.md), [design](../design/20261027-i029-adxm-lock.md)). Submodules unchanged (rexbox v0.0.17 `f4a6a48`).

Verified: on a Linux machine (Ubuntu 26.04, GCC 15.2, CMake 4.2, RTX 4090) generation takes 4 min 55 s, a fresh-tree x64 Release build has 0 warnings, CTest passes 7/7, hidden 100–150 s runs have no stop, and the 3D demo runs at about 59 fps; with the adapter the demo shows real lock contention and mixed priorities (each reported once) with no stop or timeout report; after the rebase onto v0.0.14, Win32 regenerates, builds x86 Release, passes CTest 7/7 and runs a 150 s demo with audio on without a stop (57–59 fps), and Linux x64 (rexbox v0.0.17) regenerates, builds with 0 warnings, passes CTest 7/7 and runs a 120 s hidden demo without a stop (about 59 fps).

Known limits: **the music repeating one 0.34 s section during play (issue #29) remains**; the adapter did not remove it. Once it starts the music output buffer stops changing and the ADX file reads stop; the three CRI servers running in parallel on the host are the candidate cause ([work log i029](../work-logs/20261027-i029-adxm-lock.md)). The x86 build on the Linux machine was not checked (the i386 packages `libxss-dev:i386` and `libxtst-dev:i386` were missing). After updating, **run `scripts/recomp/regenerate.py` again** (the adapter functions leave the lift and gain `_gen` bodies).
