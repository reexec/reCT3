## reCT3 v0.0.24

이전 릴리스 **v0.0.23** 이후의 변경입니다(issue #41, 2차). **새 텍스처를 만들 때의 멈춤이 사라집니다.** rexbox를 v0.0.30으로 올려, 경주 시작 같은 구역 진입에서 작은 텍스처 하나에 3~14 ms를 쓰던 일이 없어졌습니다.

### 바뀐 것

* rexbox v0.0.28 → **v0.0.30**(`682cdaf`).
  * v0.0.29(rexbox #80, #81): `REXBOX_D3D8_SLOW_FRAME`의 느린 프레임 보고에 대기·잠금·파일 읽기, 텍스처 업로드·새 프로그램 상세가 붙는다.
  * v0.0.30(rexbox #83): 느린 프레임의 단계별 시간·양·`oncpu`. 2D 텍스처 저장소를 `glTexStorage2D`로 한 번에 정한다.
* 문서: 작업 로그 i041(2차), ARCHITECTURE의 서브모듈 항목.

## reCT3 v0.0.24 (English)

Changes since **v0.0.23** (issue #41, part 2). **Making new textures no longer stalls.** rexbox moves to v0.0.30, so area entries such as the race start no longer spend 3–14 ms on one small texture.

Issue: #41, frame pacing part 2, diagnosing what slow frames spend their time on and giving textures their storage up front; the issue stays open (this PR).

Changes:

* rexbox v0.0.28 → **v0.0.30** (`682cdaf`).
  * v0.0.29 (rexbox #80, #81): `REXBOX_D3D8_SLOW_FRAME`'s slow-frame report gains waits, locks and file reads, and texture-upload and new-program detail.
  * v0.0.30 (rexbox #83): per-phase time, volume and `oncpu` for slow frames; 2D textures get their storage at once with `glTexStorage2D`.
* Documents: work log i041 (part 2), ARCHITECTURE's submodule entry.

Verified: Win32 x86 Release, CTest 7/7. West Coast drives: driving slow frames (over 20 ms) 189 → 80 and 54, texture GL time in slow frames 190.7 ms → 0.1 ms; no GL errors, captures correct.

Known limits:

* Present stalls (occasional 0.2–0.6 s while driving) and the rest of the dense frames' CPU remain (#41).
* After moving to this version, run `git submodule update`.
* Windows Defender may flag the built `rect3.exe` as `Trojan:Win32/Bearfoos.B!ml` (a machine-learning verdict); excluding the build folder avoids it.
