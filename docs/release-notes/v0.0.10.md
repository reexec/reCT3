## reCT3 v0.0.10

이전 릴리스 **v0.0.9** 이후의 변경입니다(issue #20 1차). **rexbox를 v0.0.10에 고정해 운전 화면의 D3D8 그리기 비용을 줄였습니다(그리기 단계 16~24%, CPU 프레임당 1.8~4 ms).**

### issue

| issue | 내용 | 커밋 |
|---|---|---|
| [#20](https://github.com/reexec/reCT3/issues/20) | 운전 화면 D3D8 그리기 하나의 CPU 비용, 1차. rexbox #23(issue는 열린 채 다음 단계가 이어진다) | `3b2311b`, `0b093a8`, `d3567c5` 및 이 릴리스 커밋 |

### 바뀐 것

* **submodule**: `third_party/rexbox`를 v0.0.10(`1b0aebe`, rexbox `main`의 머지 커밋)에 고정한다. 상태 읽기, 프로그램 조회 재사용, 범위별 VAO, 상수 계산 생략이 들어 있다.
* **측정**: 운전 중 GL 호출은 v0.0.9에서 프레임당 약 8000번이었다(`glVertexAttribPointer` 약 3000). 같은 프레임 안 정점 재비교는 약 800개 중 31~39개다.
* **분석**: §7에 GL 호출 수와 결과를 적었다.

### 확인한 것

| 구성 | 확인 |
|---|---|
| Win32 x86 Release | 빌드 오류 0, CTest 5/5(rexbox 3/3) |
| 운전, 느린 기계 | 18.5 → 20.7 fps, CPU 32.0 → 28.0 ms |
| 운전, 빠른 기계 | 28.2 → 27.8 fps, CPU 23.5 → 21.7 ms |
| 그림 | 어트랙트 데모 frame 1500, 운전 frame 2700 덤프 정상 |

### 알려진 한계

* 빠른 상태에서 fps가 그대로다. 바쁜 시간(약 25 ms)이 vblank 둘 근처라 줄어든 시간이 대기로 바뀌었다. 게임은 아직 실시간보다 느리다.
* 어트랙트 데모 중 드문 정지(issue #18, 열림).
* 이 버전으로 올린 뒤 `git submodule update --recursive`를 하고 다시 빌드한다(재생성 필요 없음).

## reCT3 v0.0.10 (English)

Changes since **v0.0.9** (first pass of issue #20). **rexbox is pinned to v0.0.10, which cuts the D3D8 draw cost while driving (draw phases −16–24%, CPU −1.8–4 ms per frame).**

Issue: #20, the CPU cost of one D3D8 draw while driving, first pass; rexbox #23 (the issue stays open for the next steps; `3b2311b`, `0b093a8`, `d3567c5` and this release's commit).

Changes: `third_party/rexbox` is pinned to v0.0.10 (`1b0aebe`, the merge commit on rexbox's `main`), with state reads through host pointers, program lookups reusing the previous result, a VAO per range and constants formed only on change. Measured: about 8000 GL calls per frame while driving on v0.0.9 (about 3000 `glVertexAttribPointer`), and 31–39 of about 800 vertex ranges compared again within a frame; analysis section 7 records these and the results.

Verified: Win32 x86 Release with no build errors, CTest 5/5 (rexbox 3/3); driving on the slow machine 18.5 → 20.7 fps and CPU 32.0 → 28.0 ms, on the fast machine 28.2 → 27.8 fps and CPU 23.5 → 21.7 ms; dumps of attract-demo frame 1500 and driving frame 2700 are fine.

Known limits: fps stays level in the fast state, since the busy time (about 25 ms) sits near two vblanks and the saved time became waiting; the game is still slower than real time. The rare attract-demo stop (issue #18) is open. After updating, run `git submodule update --recursive` and rebuild (no regeneration needed).
