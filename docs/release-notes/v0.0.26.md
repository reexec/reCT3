## reCT3 v0.0.26

이전 릴리스 **v0.0.25** 이후의 변경입니다(issue #49). **lifter를 upstream xboxrecomp v0.17.0으로 올립니다.** 생성 코드가 원본 x86에 더 가까워지고(호출 경계를 넘는 플래그, 함수가 끝날 때 호출자의 EBP 복원, 시프트 횟수 마스크 등), 미구현 명령이 실행되면 런타임이 보고합니다.

### 진행한 issue

| issue | 내용 | 커밋 |
|---|---|---|
| [#49](https://github.com/reexec/reCT3/issues/49) | xboxrecomp v0.17.0 적용 검토(조건부 적용 판단)와 적용, D3DXMatrixInverse decomp의 끝 EBP 수정 | `5d8b8de`, `bb941d0`, `81a2929`, `998bf6d`, `86867b7` |

### 바뀐 것

* **submodule**: `third_party/xboxrecomp`를 upstream v0.15.0(`6376eb8`)에서 **v0.17.0**(`343b6d8`)으로 올린다.
* **decomp**: `sub_000E4CB7`(D3DXMatrixInverse)이 끝날 때 `g_ebp`·`g_seh_ebp`를 호출자의 EBP로 되돌린다. v0.15.0의 lift는 이 함수의 프레임을 남겼고 decomp가 그것에 맞춰져 있었다. 둘은 함께 바뀌어야 한다.
* **생성 결과**(일본판): 함수 4,932 → 4,917, C 717,737 → 672,296줄, 미구현 명령 22 → 16곳(이제 `[recomp] untranslated instruction`으로 보고), 미해결 스텁 0 → 1(`sub_001232E1`, 호출자 없는 영역). HLE override 257개와 `check_hle_pops.py` 결과는 그대로다.
* 문서: 설계·작업 지시·작업 로그 i049, ARCHITECTURE, README, PROJECT_CHARTER, THIRD_PARTY_NOTICES, Win32 가이드, 분석 `d3dx-matrix.md`, 설계 i027 메모.

### 확인한 것 (Linux 실기: Ubuntu 26.04, GCC 15.2, RTX 4090)

| 구성 | 확인 |
|---|---|
| Linux x64 Release | 경고 0, CTest 7/7. 숨김 100초: 3D 데모 59.8~60.0 fps, 멈춤·`[recomp]` 보고 없음 |
| Linux x86 Release | 경고 0, CTest 7/7. 숨김 100초(`SDL_VIDEO_DRIVER=x11`): 3D 데모 59.5~60.0 fps, 멈춤·`[recomp]` 보고 없음 |

### 알려진 한계

* **생성 코드가 있는 Win32 x86 빌드·CTest·실행은 확인하지 않았다**(Windows 기계 필요). CI는 생성 코드 없이 빌드한다.
* 어트랙트 데모 밖의 장면(주행 등)은 확인하지 않았다.
* 이 버전으로 올린 뒤 `git submodule update`와 `regenerate.py`를 실행해야 한다.

## reCT3 v0.0.26 (English)

Changes since **v0.0.25** (issue #49). **The lifter moves to upstream xboxrecomp v0.17.0.** The generated code gets closer to the original x86 (flags across call boundaries, the caller's EBP restored when a function returns, masked shift counts and more), and the runtime reports an unimplemented instruction when one runs.

Issue: #49, reviewing xboxrecomp v0.17.0 (verdict: adopt with changes) and adopting it, with the closing EBP of the D3DXMatrixInverse decompilation fixed (`5d8b8de`, `bb941d0`, `81a2929`, `998bf6d`, `86867b7`).

Changes:

* `third_party/xboxrecomp` moves from upstream v0.15.0 (`6376eb8`) to **v0.17.0** (`343b6d8`).
* `sub_000E4CB7` (D3DXMatrixInverse) restores `g_ebp` and `g_seh_ebp` to the caller's EBP on return; v0.15.0's lift left the function's own frame there and the decompilation matched it. The two move together.
* Generated output (Japan build): 4,932 → 4,917 functions, 717,737 → 672,296 lines of C, 22 → 16 unimplemented instructions (now reported as `[recomp] untranslated instruction`), 0 → 1 unresolved stub (`sub_001232E1`, in a region with no callers). The 257 HLE overrides and `check_hle_pops.py` are unchanged.
* Documents: design, work order and work log i049, ARCHITECTURE, README, PROJECT_CHARTER, THIRD_PARTY_NOTICES, the Win32 guide, the analysis `d3dx-matrix.md`, a note in design i027.

Verified on a Linux machine (Ubuntu 26.04, GCC 15.2, RTX 4090): Linux x64 Release with 0 warnings, CTest 7/7, and a hidden 100 s run with the 3D demo at 59.8–60.0 fps and no stop or `[recomp]` report; Linux x86 Release the same with `SDL_VIDEO_DRIVER=x11`, 3D demo at 59.5–60.0 fps.

Known limits:

* **The Win32 x86 build, CTest and run with generated code are not checked** (a Windows machine is needed); CI builds without generated code.
* Scenes outside the attract demo (driving and so on) are not checked.
* After moving to this version, run `git submodule update` and `regenerate.py`.
