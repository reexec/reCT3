## reCT3 v0.0.12

이전 릴리스 **v0.0.11** 이후의 변경입니다(issue #25). **Linux x64와 x86에서 게임이 빌드되고 어트랙트 데모까지 실행됩니다(WSL2). rexbox는 v0.0.14에 고정합니다.**

### 해결된 issue

| issue | 내용 | 커밋 |
|---|---|---|
| [#25](https://github.com/reexec/reCT3/issues/25) | Linux x64 / x86 빌드와 첫 실행(WSL2 단계). 실기 확인은 이 issue에 이어 붙인다 | `4b9c55f` |

### 바뀐 것

* **submodule**: `third_party/rexbox`를 v0.0.14(`befa752`, rexbox `main`의 머지 커밋)에 고정한다. v0.0.13은 Linux GCC 경고 두 개 제거, v0.0.14는 생성 코드 없는 트리(CI)의 GNU ld 링크 순서 수정이다.
* **Linux 빌드**: `CMakePresets.json`(`linux-{x64,x86}-{debug,release}`, Ninja)과 `scripts/build_linux.sh [x64|x86] [debug|release] [--no-test]`. `RECT3_BUILD_DIR`이 있으면 빌드 트리를 그 아래에 둔다(WSL2에서 `/mnt` 밖에).
* **CI**: Linux x64 debug/release 작업(ubuntu-24.04). x86은 러너의 i386 패키지 설치가 실패해(rexbox CI와 같음) 넣지 않았다.
* **문서**: [Linux 가이드](../guides/linux-setup-and-build.md), README 플랫폼 표, 설계·작업 지시·작업 로그.
* 코드 변경 없음: Windows에서 만든 생성 코드(`gen/ct3_jp`)가 GCC로 그대로 컴파일되고 64비트 호스트에서 그대로 돈다.

### 확인한 것

| 구성 | 확인 |
|---|---|
| Win32 x86 Release | 빌드 오류 0, CTest 6/6 |
| Linux x64 Release(WSL2 Ubuntu 24.04, GCC 13) | 빌드 오류·경고 0, CTest 6/6. 숨김 실행 100초 멈춤 없음: 타이틀 60 fps, 3D 데모 46 fps(llvmpipe). WSLg 창·호스트 오디오·게임패드 포트 열림 |
| Linux x86 Release(-m32) | 빌드 오류·경고 0, CTest 6/6. 숨김 실행 150초 멈춤 없음: 타이틀 60 fps, 3D 데모 22~28 fps |
| 프레임 덤프 | x64 frame 4200 택시·지형·자막 정상, x86 frame 4200 운전자 카드 정상 |

### 알려진 한계

* WSL2는 llvmpipe(소프트웨어 렌더링)이고 soft-dirty 페이지 추적이 없다. fps는 실기 수치가 아니다. Linux 실기 확인은 아직이다.
* 3D 데모 시작이 Win32보다 늦다(frame 3000~3600 vs 2100~3000). `/mnt`의 자산 읽기 속도 때문으로 **추정**한다.
* `regenerate.py`를 Linux에서 돌리는 것은 확인하지 않았다.
* 이 버전으로 올린 뒤 `git submodule update --recursive`를 하고 다시 빌드한다(재생성 필요 없음).

## reCT3 v0.0.12 (English)

Changes since **v0.0.11** (issue #25). **The game builds and runs to the attract demo on Linux x64 and x86 (WSL2), and rexbox is pinned to v0.0.14.**

Issue: #25, the Linux x64 / x86 build and first run (the WSL2 stage; the Linux-machine check is appended to the issue; `4b9c55f`).

Changes: `third_party/rexbox` is pinned to v0.0.14 (`befa752`, the merge commit on rexbox's `main`; v0.0.13 removes two Linux GCC warnings, v0.0.14 fixes the GNU ld link order of a tree without generated code, the CI configuration). `CMakePresets.json` (`linux-{x64,x86}-{debug,release}`, Ninja) and `scripts/build_linux.sh [x64|x86] [debug|release] [--no-test]`, with `RECT3_BUILD_DIR` placing the tree elsewhere (off `/mnt` on WSL2). CI gains Linux x64 debug and release jobs (ubuntu-24.04); x86 is left out because the runner's i386 package install fails, as in rexbox's CI. The [Linux guide](../guides/linux-setup-and-build.md), README's platform table, design, work order and work log. No code change: the generated code made on Windows (`gen/ct3_jp`) compiles under GCC and runs on a 64-bit host as it is.

Verified: Win32 x86 Release with 0 build errors and CTest 6/6. Linux x64 Release (WSL2 Ubuntu 24.04, GCC 13) with 0 errors and warnings and CTest 6/6; a hidden 100 s run with no stop, the title at 60 fps and the 3D demo at 46 fps (llvmpipe); a WSLg window with host audio and a gamepad port. Linux x86 Release (-m32) with 0 errors and warnings and CTest 6/6; a hidden 150 s run with no stop, the title at 60 fps and the demo at 22–28 fps. Frame 4200 dumps are correct on both (the taxi, terrain and caption on x64; a driver card on x86).

Known limits: WSL2 renders with llvmpipe and has no soft-dirty page tracking, so its fps is not a real machine's, and the Linux-machine check is still to come; the 3D demo starts later than on Win32 (frames 3000–3600 against 2100–3000), **inferred** to be the asset reads over `/mnt`; `regenerate.py` on Linux is not verified. After updating, run `git submodule update --recursive` and rebuild (no regeneration needed).
