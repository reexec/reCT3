## reCT3 v0.0.6

이전 릴리스 **v0.0.5** 이후의 변경입니다(issue #11). **rexbox를 머지된 v0.0.6에 고정하고, 도시 장면이 30 fps로 돕니다.**

### 해결된 issue

| issue | 내용 | 커밋 |
|---|---|---|
| [#11](https://github.com/reexec/reCT3/issues/11) | 도시 장면의 프레임 시간: P8 텍스처의 팔레트별 캐시(rexbox #16), 게임 속도 측정 | `6506b0c` |

### 바뀐 것

* **submodule**: `third_party/rexbox`를 v0.0.6(`bc46161`, rexbox `main`의 머지 커밋)에 고정한다. rexbox v0.0.6은 P8 텍스처를 팔레트마다 따로 캐시한다.
* **원인**: 타이틀은 같은 P8 텍스처(차량 등)를 한 프레임에 최대 7개 팔레트로 그린다. rexbox가 팔레트가 바뀔 때마다 다시 디코딩해(프레임당 최대 42회) `setup`이 프레임당 최대 12.4 ms였다.
* **분석**: 프레임 구조(로직 60 Hz, 화면 30 fps는 타이틀의 설계, 게임 진행 속도는 정상). 분석 문서 §7, 작업 지시와 작업 로그.

### 확인한 것

| 구성 | 확인 |
|---|---|
| Win32 x86 Release | 빌드 오류 0, CTest 5/5 |
| 도시 장면(300프레임 구간) | 22.0~26.1 fps → 27.9~30.0 fps, `setup` 5.9~12.4 ms → 1.2~2.3 ms, CPU 19.3 → 9.5~12.8 ms |
| 화면 | frame 1500·2100: 지형·간판 정상, 차량 색이 따로 그려진다 |

### 알려진 한계

* 가장 나쁜 프레임 43~99 ms, 장면 전환(로딩) 구간 100~130 ms.
* 이 버전으로 올린 뒤 `git submodule update --recursive`를 하고 다시 빌드한다(재생성 필요 없음).
* rexbox의 Linux CI는 러너의 i386 패키지 설치 문제로 v0.0.3부터 돌지 않는다(이 저장소의 CI는 Win32만 돈다).

## reCT3 v0.0.6 (English)

Changes since **v0.0.5** (issue #11). **rexbox is pinned to the merged v0.0.6, and the city scenes run at 30 fps.**

Resolved: #11, frame time in the city scenes: P8 textures cached per palette (rexbox #16) and the game's speed measured (`6506b0c`).

Changes: `third_party/rexbox` is pinned to v0.0.6 (`bc46161`, the merge commit on rexbox's `main`), which caches P8 textures per palette. The cause: the title draws the same P8 texture (vehicles and the like) with up to 7 palettes in a frame, and rexbox decoded it again at every switch (up to 42 per frame), with `setup` at up to 12.4 ms per frame. The analysis records the frame structure (60 Hz logic, a 30 fps picture by the title's design, the right game speed); analysis section 7, the work order and the work log are updated.

Verified: Win32 x86 Release with no build errors and CTest 5/5; over 300-frame spans in the city, 22.0–26.1 fps became 27.9–30.0 fps, `setup` 5.9–12.4 ms became 1.2–2.3 ms, and CPU time 19.3 ms became 9.5–12.8 ms; frames 1500 and 2100 draw the geometry and signs correctly, with each vehicle colour drawn separately.

Known limits: worst frames of 43–99 ms, and 100–130 ms at scene changes (loading). After updating, run `git submodule update --recursive` and rebuild (no regeneration needed). rexbox's Linux CI has not run since v0.0.3 because the runner's i386 package install fails (this repository's CI runs Win32 only).
