## reCT3 v0.0.9

이전 릴리스 **v0.0.8** 이후의 변경입니다(issue #17). **운전 화면의 프레임 시간을 측정해 나누었고, rexbox를 v0.0.9에 고정해 추적 문장 서식 비용(프레임당 약 3.5 ms)을 없앴습니다. 가장 큰 비용(D3D8 그리기, 프레임당 14.8 ms)은 rexbox #23에 설계했습니다.**

### 해결된 issue

| issue | 내용 | 커밋 |
|---|---|---|
| [#17](https://github.com/reexec/reCT3/issues/17) | 운전 화면 약 25 fps(게임 시간 0.43배): 프레임 측정과 가장 큰 비용의 설계. rexbox #22, #23 | `aeec88a`, `7735f85` 및 이 릴리스 커밋 |

### 바뀐 것

* **submodule**: `third_party/rexbox`를 v0.0.9(`b2f2653`, rexbox `main`의 머지 커밋)에 고정한다. 추적이 꺼져 있을 때 D3D8 추적 문장을 만들지 않는다.
* **측정**(i5-7200U + HD 620, 그리기 약 810개): 42.4 ms = vblank 대기 8.3 + D3D8 그리기 14.8 + present 1.3 + 그 밖 17.9(lift된 코드 약 9, 추적 문장 서식 약 3.5). 비용은 표시 스레드의 CPU이며 GPU가 아니다. vsync 끔, 숨긴 창, 렌더 배율 2는 차이가 없었다.
* **스크립트**: `scripts/drive_west_coast.ps1`이 게임 창에 키 메시지를 보내 West Coast 운전까지 간다(환경 변수는 게임 프로세스에만). 절차는 [가이드](../guides/driving-measurement.md).
* **분석**: §7에 운전 프레임 구성, 드문 정지(issue #18), 출처를 모르는 `NtWriteFile`을 적었다.

### 확인한 것

| 구성 | 확인 |
|---|---|
| Win32 x86 Release | 빌드 오류 0, CTest 5/5(rexbox 3/3) |
| 운전, 표본 | ucrtbase 13.2% → 2.7%, 프레임당 표본 20.5 → 17.3 |
| 운전, 짝 실행 | `other` 15.6 → 12.1 ms, CPU 27.2 → 24.7 ms, 27.3 → 28.4 fps |

### 알려진 한계

* fps는 거의 그대로다. 바쁜 시간이 vblank 둘 근처라 프레임이 여전히 vblank 2~3개이고, 게임은 실시간보다 느리다. 다음은 rexbox #23 구현이다.
* 어트랙트 데모 중 드물게 `000C11B1`의 null vtable 호출 뒤 멈춘다(issue #18, 열림).
* 이 버전으로 올린 뒤 `git submodule update --recursive`를 하고 다시 빌드한다(재생성 필요 없음).

## reCT3 v0.0.9 (English)

Changes since **v0.0.8** (issue #17). **The driving frame is measured and split, and rexbox is pinned to v0.0.9, which removes the trace-text formatting cost (about 3.5 ms per frame). The largest cost (D3D8 drawing, 14.8 ms per frame) is designed in rexbox #23.**

Resolved: #17, driving at about 25 fps (game time 0.43×): the frame measured and its largest cost designed; rexbox #22 and #23 (`aeec88a`, `7735f85` and this release's commit).

Changes: `third_party/rexbox` is pinned to v0.0.9 (`b2f2653`, the merge commit on rexbox's `main`), which builds no D3D8 trace text while tracing is off. Measurement (i5-7200U + HD 620, about 810 draws): 42.4 ms = vblank wait 8.3 + D3D8 drawing 14.8 + present 1.3 + other 17.9 (lifted code about 9, trace-text formatting about 3.5); the cost is the presenting thread's CPU, not the GPU, and vsync off, a hidden window and render scale 2 made no difference. `scripts/drive_west_coast.ps1` posts key messages to the game window to reach West Coast driving (environment variables for the game's process only); procedure in the [guide](../guides/driving-measurement.md). Analysis section 7 records the driving frame, a rare stop (issue #18) and an `NtWriteFile` of unknown source.

Verified: Win32 x86 Release with no build errors, CTest 5/5 (rexbox 3/3); driving samples: ucrtbase 13.2% → 2.7%, samples per frame 20.5 → 17.3; paired runs: `other` 15.6 → 12.1 ms, CPU 27.2 → 24.7 ms, 27.3 → 28.4 fps.

Known limits: fps barely moves, since the busy time sits near two vblanks and frames still take two or three; the game is still slower than real time, and rexbox #23's implementation is next. The attract demo rarely stops after a null vtable call at `000C11B1` (issue #18, open). After updating, run `git submodule update --recursive` and rebuild (no regeneration needed).
