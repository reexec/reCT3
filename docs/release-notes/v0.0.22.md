## reCT3 v0.0.22

이전 릴리스 **v0.0.21** 이후의 변경입니다(issue #44, #41). **부팅 초기에 가끔 나던 null 간접 호출(`000B27B0`)을 고치고, rexbox를 v0.0.23으로 올립니다.**

### 해결된 issue

| issue | 내용 | 커밋 |
|---|---|---|
| [#44](https://github.com/reexec/reCT3/issues/44) | 부팅 초기의 null 간접 호출: ADXF Close가 파일 서버의 두 읽기 사이에 객체를 지움 | `be3bc75`, `2b9eb80`, `4195b8e`, `6e9be40` |

### 바뀐 것

* `src/game/ct3/decomp/adxm_lock.c`: ADXF Close(`000B2A90`)를 ADXM 호스트 잠금 아래에서 돌게 했다.
  * Close는 읽는 중(상태 2)일 때만 잠금을 잡는 정지 경로를 거치고, 객체 0x138바이트를 잠금 없이 0으로 지운다.
  * 부팅 때 AFS 파티션 표를 읽는 코드가, 읽기가 끝나자마자(상태 3) Close를 불렀다. 파일 서버가 막 상태를 바꾸고 스트림 필드를 두 번 읽는 사이에 Close가 끼어들었다.
  * Xbox에서는 서버 실행이 게임 스레드보다 높은 우선순위라 끼어들 수 없었다([설계](../design/20261106-i044-adxt-stop-lock.md)).
* rexbox v0.0.21 → **v0.0.23**(`25587f7`, #41의 준비): XDK 5849 LTCG 지원, 로딩 스레드에서 그리는 타이틀의 창 스레드 수정, `RtlLeaveCriticalSection`이 첫 대기자에게 구간을 넘김. 이 마지막 변경으로 스레드 순서가 바뀌어 #44가 더 자주 드러났다.
* 분석 `docs/analysis/cri-middleware.md` §5에 ADXF 객체 표와 Close 경로를 더했다. `decomp/README.md`, ARCHITECTURE를 갱신했다.
* 문서: 설계·작업 지시·작업 로그 i044.

### 확인한 것

| 구성 | 확인 |
|---|---|
| Win32 x86 Release | 경고 0, CTest 7/7 |
| 숨긴 데모 6개 동시 실행 | 수정 전(v0.0.23) 42번 중 null 호출 6번 → 수정 후 48번 중 0번. 음악 멈춤·다른 스트림 멈춤·stall·잠금 시한도 0 |
| 운전 진입 | West Coast 운전 구간 59.5~59.8 fps, 이상 없음 |

### 알려진 한계

* 영상 구간의 null 간접 호출(`000C967E`)은 별개의 CRI 경합으로 보이며 남아 있다(드묾).
* 이 버전으로 올린 뒤 `git submodule update`와 `scripts/recomp/regenerate.py`를 다시 실행해야 한다(새 대체 함수 `000B2A90`).
* Windows Defender가 빌드한 `rect3.exe`를 `Trojan:Win32/Bearfoos.B!ml`(머신러닝 판정)로 오탐할 수 있다. 빌드 폴더를 제외에 두면 된다.

## reCT3 v0.0.22 (English)

Changes since **v0.0.21** (issues #44, #41). **Fixes a null indirect call (`000B27B0`) that sometimes happened early in boot, and moves rexbox to v0.0.23.**

Issue: #44, the null indirect call early in boot, ADXF Close zeroing an object between the file server's two reads (`be3bc75`, `2b9eb80`, `4195b8e`, `6e9be40`).

Changes:

* `src/game/ct3/decomp/adxm_lock.c` runs ADXF Close (`000B2A90`) under the ADXM host lock.
  * Close goes through the locked stop path only while the object is reading (state 2), and zeroes its 0x138 bytes with no lock.
  * The code that reads the AFS partition table at boot called Close as soon as the read was done (state 3). It landed while the file server, having just changed the state, read the stream field twice.
  * On the Xbox the server pass ran above the game thread and could not be interrupted ([design](../design/20261106-i044-adxt-stop-lock.md)).
* rexbox v0.0.21 → **v0.0.23** (`25587f7`, groundwork for #41): XDK 5849 LTCG support, window-thread fixes for titles that draw from a loading thread, and `RtlLeaveCriticalSection` handing the section to the first waiter. That last change alters the thread order and made #44 show more often.
* The analysis `docs/analysis/cri-middleware.md` section 5 adds the ADXF object table and the Close path; `decomp/README.md` and ARCHITECTURE are updated. Design, work order and work log i044.

Verified: Win32 x86 Release with 0 warnings and CTest 7/7. Batches of six hidden demos in parallel: 6 null calls in 42 runs before the fix (v0.0.23), 0 in 48 after, with no music stop, other stream stop, stall or lock timeout. A drive into gameplay: 59.5–59.8 fps in the West Coast driving section, no issues.

Known limits:

* The null indirect call in the movie (`000C967E`) looks like a separate CRI race and remains (rare).
* After moving to this version, run `git submodule update` and `scripts/recomp/regenerate.py` again (new replacement `000B2A90`).
* Windows Defender may flag the built `rect3.exe` as `Trojan:Win32/Bearfoos.B!ml` (a machine-learning verdict); excluding the build folder avoids it.
