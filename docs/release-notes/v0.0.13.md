## reCT3 v0.0.13

이전 릴리스 **v0.0.12** 이후의 변경입니다(issue #27). **운전 화면에서 표본이 가장 많던 D3DX 행렬 함수 세 개를 디컴파일하고, 디컴파일 함수를 lift 원본과 비교하는 검사 도구를 더합니다.**

### 해결된 issue

| issue | 내용 | 커밋 |
|---|---|---|
| [#27](https://github.com/reexec/reCT3/issues/27) | 행렬 함수 `000E4B73`, `000E4BB9`, `000E4CB7` 디컴파일, `rect3_decomp_check` | `82ac120`, `3fd875f` |

### 바뀐 것

* **디컴파일**(`src/game/ct3/decomp/d3dx_matrix.c`, 첫 디컴파일 함수): 정적 링크된 D3DX의 `D3DXVec4Transform`(`000E4B73`), `D3DXMatrixMultiply`(`000E4BB9`), `D3DXMatrixInverse`(`000E4CB7`)로 **추정**되는 함수. 일반 C로 같은 연산·순서를 계산하고, 레지스터, XMM, x87 스택, 메모리 부수 효과를 원본과 같게 남긴다. 역행렬은 lifter와 같은 연산별 정밀도 제어 반올림을 한다. 분석: [d3dx-matrix](../analysis/d3dx-matrix.md), 설계: [i027](../design/20261026-i027-matrix-decomp.md).
* **검사 도구 `rect3_decomp_check`**(`tools/decomp_check/`): 디컴파일 함수와 lift 원본(`sub_X_gen`)을 같은 상태에서 돌려 GPR, `g_seh_ebp`, XMM0~7, x87 제어어·top·슬롯, 게스트 메모리 전체를 비교한다. 생성 코드가 있을 때만 빌드되고 CTest에 등록된다.
* **문서**: ARCHITECTURE(검사 도구, rexbox v0.0.14 표기 수정), `decomp/README.md`, Win32·Linux 가이드, 설계·작업 지시·작업 로그·분석.
* submodule 변경 없음(rexbox v0.0.14 `befa752`).

## reCT3 v0.0.13 (English)

Changes since **v0.0.12** (issue #27). **Decompiles the three D3DX matrix routines that led the driving frame's samples, and adds a checker that compares decompiled functions with their lifted originals.**

Resolved: #27, decompiling `000E4B73`, `000E4BB9` and `000E4CB7`, and `rect3_decomp_check` (`82ac120`, `3fd875f`).

Changes: the first decompiled functions (`src/game/ct3/decomp/d3dx_matrix.c`), **inferred** to be the statically linked D3DX `D3DXVec4Transform`, `D3DXMatrixMultiply` and `D3DXMatrixInverse`, compute the same operations in the same order in plain C and leave the registers, XMM, x87 stack and memory side effects as the originals do, the inverse with the lifter's per-operation precision-control rounding ([analysis](../analysis/d3dx-matrix.md), [design](../design/20261026-i027-matrix-decomp.md)). `rect3_decomp_check` (`tools/decomp_check/`, built with generated code only and registered with CTest) runs each against its lifted original (`sub_X_gen`) and compares the GPRs, `g_seh_ebp`, XMM0–7, the x87 control word, top and slots, and all of guest memory. Docs: ARCHITECTURE (the checker, and the rexbox v0.0.14 pin fixed), `decomp/README.md`, the Win32 and Linux guides, design, work order, work log and analysis. Submodules unchanged (rexbox v0.0.14 `befa752`).

Verified: `rect3_decomp_check` has 0 differences in 50 cases on Win32 Debug and Release and Linux x64 and x86 (WSL2), and catches three faults injected on purpose; Win32 and Linux build with 0 warnings and CTest 7/7; in the driving span, alternating with v0.0.12, the title code (`other`) went from 3.30 to 2.83 ms and from 2.76 to 2.47–2.50 ms in two batches, and the three functions' samples from 165 to 105; repeated entries into driving: no stall in 6 runs of the final version or 12 of the baseline.

Known limits: the first version stalled once in 9 entries into driving, in the loading wait loop, unexplained; the x87 slots were then made to match too, so every compared state matches, and a recurrence is treated as a rare existing problem like issue #18. After updating, **run `scripts/recomp/regenerate.py` again** (the decompiled functions leave the lift and gain `_gen` bodies), then rebuild.
