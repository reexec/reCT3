* 문서: 설계 i029 SJ 잠금, i029 작업 지시·작업 로그, 분석, decomp README, ARCHITECTURE.
* submodule 변경 없음(rexbox v0.0.19 `7704477`).

## reCT3 v0.0.18 (English)

Changes since **v0.0.17** (issue #29). **Fixes the music repeating one 0.34 s stretch during play.**

Resolved: #29, the music repeat, with a host lock for CRI's SJ critical section (`603db36` and the last commit of this release).

Changes: `src/game/ct3/decomp/sj_lock.c` wraps `000BC950`/`000BC970`, the critical section CRI's SJ ring-buffer functions enter and leave, in a rexbox guest lock; it is empty in this build, so on the host the file server thread and the ADX server thread updated the music's input ring together, leaking its bytes until the stream stopped ([design](../design/20261103-i029-sj-lock.md), [analysis](../analysis/cri-middleware.md) section 4). Documents: design i029 SJ lock, the i029 work order and work log, the analysis, the decomp README, ARCHITECTURE. Submodules unchanged (rexbox v0.0.19 `7704477`).

Verified: Linux x64 Release with 0 warnings and CTest 7/7; three hidden 400 s demos in parallel (a comparison): without the fix 3/3 reproduced (5 reports), with it 0/3.

Known limits: after updating, **run `scripts/recomp/regenerate.py` again** (`000BC950` and `000BC970` leave the lift and gain `_gen` bodies); if the repeat returns in play, attach the default log's `[dsound] ... its writer stopped` report to the issue.
