## reCT3 v0.0.23

이전 릴리스 **v0.0.22** 이후의 변경입니다(issue #41, 1차). **밀집 주행 장면의 프레임률이 오릅니다.** rexbox를 v0.0.28로 올려, 모든 draw가 정점 배열(VAO) 하나를 씁니다.

### 진행한 issue

| issue | 내용 | 커밋 |
|---|---|---|
| [#41](https://github.com/reexec/reCT3/issues/41) | 프레임 페이싱 1차: 밀집 장면의 GL 드라이버 비용(VAO 바인드). issue는 열어 둔다 | `2e67615`, `cba134a` |

### 바뀐 것

* rexbox v0.0.23 → **v0.0.28**(`f552fac`).
  * v0.0.24~v0.0.26: 다른 타이틀을 위한 변경(텍스처 재활용, 타이틀의 픽셀 셰이더, DSOUND 진단)이다.
  * v0.0.27(rexbox #76): `REXBOX_GL_CALLS=time`으로 프레임당 GL 드라이버 시간을 진입점별로 잰다.
  * v0.0.28(rexbox #78): 캐시된 정점 구간마다 두던 VAO를 걷어냈다. 밀집 장면에서 드라이버가 VAO마다 검증하는 비용이 프레임당 수 ms였다.
* 문서: 작업 로그 i041(1차), ARCHITECTURE의 서브모듈 항목.

### 확인한 것

### 알려진 한계

* 이 버전으로 올린 뒤 `git submodule update`를 실행해야 한다.

## reCT3 v0.0.23 (English)

Changes since **v0.0.22** (issue #41, part 1). **Dense driving scenes run at a higher frame rate.** rexbox moves to v0.0.28, so every draw uses one vertex array (VAO).

Issue: #41, frame pacing part 1, the GL driver cost of dense scenes (the VAO binds); the issue stays open (`2e67615`, `cba134a`).

Changes:

* rexbox v0.0.23 → **v0.0.28** (`f552fac`).
  * v0.0.24–v0.0.26: changes for other titles (recycled textures, the title's pixel shaders, DSOUND diagnostics).
  * v0.0.27 (rexbox #76): `REXBOX_GL_CALLS=time` measures the GL driver time per frame by entry point.
  * v0.0.28 (rexbox #78): the VAO per cached vertex range is removed; in dense scenes the driver's per-VAO validation cost several ms per frame.
* Documents: work log i041 (part 1), ARCHITECTURE's submodule entry.

Verified: Win32 x86 Release with 0 warnings and CTest 7/7. In the dense stretches of a West Coast drive: 54–57 fps (12.7–14.3 ms CPU, 4.1–4.6 ms GL) before, 59.2–59.3 fps (8.3–8.9 ms CPU, 0.9 ms GL) after.

Known limits:

* Frame intervals are not steady yet (the rest of #41: the vertical-blank wait's precision, the virtual clock drifting from the monitor, the rest of the dense scenes' CPU).
* After moving to this version, run `git submodule update`.
* Windows Defender may flag the built `rect3.exe` as `Trojan:Win32/Bearfoos.B!ml` (a machine-learning verdict); excluding the build folder avoids it.
