## reCT3 v0.0.7

이전 릴리스 **v0.0.6** 이후의 변경입니다(issue #13). **rexbox를 v0.0.7에 고정합니다. 렌더 프레임이 vblank 하나로 끝나 타이틀 화면이 60 fps가 되고, 게임이 그만큼 빨라집니다.**

### 해결된 issue

| issue | 내용 | 커밋 |
|---|---|---|
| [#13](https://github.com/reexec/reCT3/issues/13) | 게임이 느림: 프레임마다 vblank 두 개(Swap이 기다리고, 타이틀이 또 기다림). rexbox #18 | `80c30e9`, `0146f29` |

### 바뀐 것

* **submodule**: `third_party/rexbox`를 v0.0.7(`0aa0126`, rexbox `main`의 머지 커밋)에 고정한다. rexbox v0.0.7의 `Swap`은 플립을 예약하고 돌아온다.
* **원인**: CT3의 게임 시간은 present 하나에 1/60초씩 간다(1200프레임에 20초). 프레임은 `D3DDevice_Swap(0)` → `D3DDevice_BlockUntilVerticalBlank()`(`000A7085`~`000A708C`)로 끝난다. rexbox의 `Swap`이 vblank까지 잠들고 타이틀이 한 번 더 기다려 30 fps 상한, 게임은 절반 속도 이하였다.
* **분석**: §7의 프레임 구조 항목을 바로잡았다(v0.0.6의 "로직 60 Hz, 화면 30 fps, 속도 정상"은 틀렸다). `0x2C2800`의 뜻 추가.

### 확인한 것

| 구성 | 확인 |
|---|---|
| Win32 x86 Release | 빌드 오류 0, CTest 5/5 |
| 타이틀 화면 | 29.5 fps → 60.0(창·vsync, 숨김, vsync 끔) |
| 데모 도시 장면(300프레임 구간) | 22.4~24.2 → 39.7~41.6 fps |
| 운전(같은 입력, `REXBOX_HLE_FALLBACK=lifted`) | 14.4 fps(실시간의 0.24배) → 19.1 fps(0.32배) |

### 알려진 한계

* 게임 속도는 fps/60이다. 시험 기계(i5-7200U, 2코어)에서는 운전 화면 CPU가 프레임당 33~40 ms라 아직 실시간보다 느리다.
* 게임 시작(Start)은 `D3DDevice_InsertFence`(`000F5050`)에서 멈춘다(`REXBOX_HLE_FALLBACK=lifted`로 지나간다). 별도 작업으로 진행 중이다.
* 이 버전으로 올린 뒤 `git submodule update --recursive`를 하고 다시 빌드한다(재생성 필요 없음).

## reCT3 v0.0.7 (English)

Changes since **v0.0.6** (issue #13). **rexbox is pinned to v0.0.7: a rendered frame takes one vblank, the title screen runs at 60 fps, and the game speeds up to match.**

Resolved: #13, the game running slowly because every frame took two vblanks (Swap waited, then the title waited again); rexbox #18 (`80c30e9`, `0146f29`).

Changes: `third_party/rexbox` is pinned to v0.0.7 (`0aa0126`, the merge commit on rexbox's `main`), whose `Swap` queues the flip and returns. The cause: CT3's game time advances 1/60 s per present (20 s in 1200 frames), and a frame ends with `D3DDevice_Swap(0)` → `D3DDevice_BlockUntilVerticalBlank()` (`000A7085`–`000A708C`); rexbox's `Swap` slept to the vblank and the title waited again, capping it at 30 fps and the game at half speed or less. The frame-structure entry in analysis section 7 is corrected (v0.0.6's "logic at 60 Hz, picture at 30 fps, speed correct" was wrong), and the meaning of `0x2C2800` is added.

Verified: Win32 x86 Release with no build errors and CTest 5/5; the title screen went from 29.5 fps to 60.0 (window with vsync, hidden, vsync off); demo city scenes from 22.4–24.2 to 39.7–41.6 fps over 300-frame spans; driving with the same input (`REXBOX_HLE_FALLBACK=lifted`) from 14.4 fps (0.24× real time) to 19.1 fps (0.32×).

Known limits: game speed is fps/60, and on the test machine (i5-7200U, two cores) driving takes 33–40 ms of CPU per frame, so it is still slower than real time. Starting a game (Start) stops at `D3DDevice_InsertFence` (`000F5050`) unless `REXBOX_HLE_FALLBACK=lifted` is set; that is separate work in progress. After updating, run `git submodule update --recursive` and rebuild (no regeneration needed).
